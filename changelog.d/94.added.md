- `escalation-summary@0.1.0`, a Haiku agent with no tools, reads one escalation record and writes one paragraph on what is blocked and what the person must decide, and up to four options, each with what it takes, what it costs and a verbatim quote from the record as evidence; four hand-written eval cases, one per trigger, are graded by rubric and by the new deterministic `expected.options_in_record` check.
- The build loop and the hotfix pipeline call `runtime.after_escalation.after_escalation` right after an escalation record is written: the summary agent runs under the run's budget, its summary is stored in the new `escalation_summaries` table (trace store migration 7) only when `runtime.escalation_summary.ungrounded` finds nothing wrong with it, and the report gains an `after_escalation` key; a budget stop and a dry run get no summary, and a failed summary never changes the item's state or the exit code.
- `factory escalations show` prints the record's summary above the record, and `--json` carries it as `summary`.
