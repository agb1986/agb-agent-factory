- `factory plan <repo> --idea TEXT|@FILE [--approve] [--json]`, the plan loop in `pipelines/plan_loop.py`: product-architect writes a PRD that is stored at `data/plans/<run-id>.md`, nothing continues until `--approve` (on the command line or on a second invocation with `--prd @FILE`), open questions are answered with `--answer "<question>=<answer>"`, and story-breakdown then files the tickets in `todo` with parent `prd:<run-id>` and their dependencies set. One pipeline run id covers both agents and the store events, and the plan loop never makes a ticket `ready`. Tickets that share an impacted path are made sequential. The guide is `docs/plan-loop.md` (#92).
