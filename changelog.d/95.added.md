- `notify.issue`, an outside write that posts an escalation and its summary to the ticket's GitHub issue: the first escalation of a ticket opens the issue, a later one comments on it, and a rerun edits its own post. The post fits GitHub's 65536-character limit by cutting the diff, agent outputs and suite tail first, closes any code fence the question or summary leaves open, and neutralizes @mentions, issue references and HTML comments with a zero-width space. It never closes, reopens, labels or assigns an issue, and honours `--dry-run` (#95).
- `factory escalations answer <id> --from-issue`, which stores the latest reply on the ticket's issue as the answer, through the same checks as `--text`. Only a comment made after the post by the repository's owner, a member or a collaborator counts, and a factory post never does; the answer's source names the issue and the comment (#95).
- Work items gain a nullable `issue_number` (trace migration 8), stored after the first post and shown by `factory ticket show` and its JSON (#95).
