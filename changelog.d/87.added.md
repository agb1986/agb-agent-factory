- `factory build <id>`, the build loop: it takes one `ready` work item to a reviewed pull request. The feature-coder builds the ticket in a clone with its file policy enforced on the host, the whole suite runs in the sandbox, and the review panel reviews the diff, with one more coder round when the panel asks for changes. When the panel ships, `github.create_pr` opens the pull request on the repository's `origin` and the item moves to `in_review`; any other end moves it to `blocked` with the stop and the report's path as the reason. `--dry-run` runs every step but opens no pull request and leaves the item `ready`. The report goes to `data/builds/<run-id>.json`, and `tests/golden/build.json` pins its `--json` document. Its live test has not been run yet (#87).
