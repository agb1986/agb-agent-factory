- `action-guard@0.1.2` and `action-guard@0.2.1` no longer refuse a write that puts a docstring into a source file when the task says it changes no code: a write replaces the whole file, so the guard does not read the code in its content as a code change, and each eval gains a case for it. This is what failed the `documentation-agent` case `document-new-class` and its live test. The 0.2 guard moves from `agents/action-guard/0.2.0/` to `agents/action-guard/0.2.1/`. The guard's live test now expects the write into a worktree under `/tmp` to be allowed, as the case added in #79 says.
