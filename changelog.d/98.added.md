- `refactorer@0.1.0`, a dev agent that takes one `refactor` ticket (the targets in `impacted_paths`, the smell or deprecated API and the standard in `body`) and changes production code without changing behaviour. Its answer lists the files changed and states what stayed the same; its file policy refuses every test file, and its prompt forbids a public signature change the ticket does not name. It runs `claude-sonnet-5-5` at effort `xhigh` behind `action-guard@^0.1`, with the fixer's tools. Its four eval cases (an N-plus-one query, duplicate code, a deprecated call, magic numbers) are graded by `sandbox_tests` with no rubric; they, its publish check and its live test have not been run yet (#98).
- `factory build` sends `refactor` tickets to the refactorer and runs a behaviour check around it (`pipelines/behaviour.py`): the whole suite with line coverage before the first round and after each passing suite. A red baseline, a test that passed before and does not after, more uncovered statements, coverage that can no longer be measured, or a committed test file stops the run with its own error and leaves the item `blocked` with the tests or coverage figures in the reason. `feature`, `bug` and `docs` tickets are unchanged (#98).
- A `sandbox_tests` eval case may set `expected.run.public_api` to a list of Python files whose public names and signatures must match the fixture's HEAD, compared with `ast` by `evals/public_api.py` (#98).
