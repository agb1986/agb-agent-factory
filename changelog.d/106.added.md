- `spike@0.1.0`, a research agent that writes throwaway code to learn how an API or a package really behaves, and reports the payload shapes, edge cases, working code and failures it saw. Every observation records the command it ran and the output it printed, and every fact it read is a cited `Claim`. It runs under a second sandbox profile, `sandbox: spike` in the manifest: the network is on, `pip` installs are allowed, no repository is mounted, the agent writes into a fresh empty directory that is removed after the run, and each command has a 90 s wall-clock limit with the same CPU and memory limits as the offline sandbox. `sandbox: true` and `sandbox: false` keep their meaning (#106).
- `action-guard@0.2.0`, which is told which sandbox profile a call runs in and judges network and install commands under the spike profile, while still refusing writes outside the scratch directory and requests to cloud metadata addresses. Agents that ask for `action-guard@^0.1` keep the 0.1 guard (#106).
