- `code-archaeology@0.1.0`, a `decomp` agent that reads a Python codebase from one entry point with read-only tools (`git.read_file`, `rg.search`, `deps.graph`, `deps.impact`, `deps.dead_code`, `deps.call_graph`) and returns a module map, the data flows between modules, the dead code with the tool's evidence for each entry, the symbols a dynamic lookup may reach apart from it, and the execution paths with every unresolved call named at its site and never guessed. Its output model, `CodeArchaeologyOutput`, is in `registry/decomposition_schemas.py` for the agent that plans an extraction (#112).
- The `ground_truth` eval grader and the `expected.ground_truth` block, which check an answer about a codebase against entries of the fixture's `ground-truth.yaml` named by id: planted dead code, data flows, call chains and dynamic calls, and in every case that no decoy is called dead and no dynamic call is reported as a plain one. A `rubric` case may carry the block too (#112).
- `extraction-modularization@0.1.0`, a `decomp` agent that takes an archaeology and one named feature, reads the code with read-only tools (`git.read_file`, `rg.search`, `deps.graph`, `deps.impact`, `deps.call_graph`) and returns an `ExtractionBlueprint`: the feature's inputs, outputs and invariants, the symbols that belong to it, what it uses, who calls it, the state it shares, the tests that pin it, and how each shared-state tie can be cut. It moves no code. Its model is in `registry/decomposition_schemas.py` (#112).
- The `features` checks of the `ground_truth` grader, which compare a blueprint's boundary and ties with a feature of the fixture's `ground-truth.yaml`; they run before the judge in the `rubric` cases of extraction-modularization (#112).
- `pipelines/decompose.py`, which renders a blueprint as markdown, makes a `refactor` ticket from it whose body holds the blueprint as JSON, reads the blueprint back from that body, and files the ticket in `todo` linked to its pipeline run. It runs no agent yet (#112).
