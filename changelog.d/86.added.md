- `feature-coder@0.1.0`, a dev agent that builds one ticket in a sandboxed work tree, writing the code and a test for every acceptance criterion a test can check, and answering `blocked` with the contradiction when the criteria contradict the code. It runs `claude-sonnet-5-5` at effort `xhigh` behind `action-guard@^0.1`, with the fixer's tools. Its four eval cases are graded by `sandbox_tests` with a rubric on the answer; they and its live test have not been run yet (#86).
- A manifest `files` block (`files.allow`, `files.deny`) declares the paths an agent's writes may touch, and `pipelines/file_policy.py` enforces it on the host. The fixer's rule against changing tests is now its file policy instead of the fix loop's `TestFileGuard`; the refusal, its trace row and `TestFileWriteError` are unchanged. The feature-coder's policy is declared but enforced by no pipeline until the build loop (#87) runs it (#86).
- An optional manifest `team` field labels every agent with its team from ADR 0002. A `sandbox_tests` eval case may carry an `expected.rubric` to check the answer's prose after the work tree. Neither `team` nor `files` needs a version bump (#86).
